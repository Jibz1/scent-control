# The listener: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** an always-on service on Railway that hears every diffuser on our broker, keeps
and shares each one's latest reported state and whether the listener itself is running,
and a Mac app that reads it.

**Architecture:** `apps/server` is a Bun/TypeScript package.
- A pure core of plain functions takes a parsed message, the clock and the memory, and
  returns the new memory plus the exact publishes to make.
- A thin Effect v4 shell owns the MQTT.js connection, the 30-second tick and start-up.
- `scent-core` (Rust) gets the matching topics and decoders, and the Mac app adopts the
  shared state with "newer wins" and the reconnect rule.

**Tech stack:** Bun 1.4.2, TypeScript, Effect 4.0.2, MQTT.js, `bun test`, oxlint and
oxfmt; Rust (`scent-core`, `scent-desktop`); Railway.

**Spec:** `docs/superpowers/specs/2026-10-22-listener-design.md` (approved 2026-10-22).
Read it before any task: §-numbers below refer to it.

**Order.** This differs from the spec's §7 on purpose. The broker update (§7 step 0)
moves to Task 7, just before the listener's deploy. That way all the code is done before
the owner is needed, and the owner is needed only once, for Tasks 7–9. The spec requires
only that the broker is up to date before the listener is deployed, and this order keeps
that.

## Global constraints

- Bun 1.4.2 (the root `packageManager`). There is one `bun.lock`, at the root, and
  `bun install` runs at the root only.
- `effect` is exactly `4.0.2`, in the root `workspaces.catalog`. Workspace packages
  declare `"effect": "catalog:"`, and every `@effect/*` package is exactly `4.0.2`.
- Effect v4 idioms only:
  - `Context.Service` with `make`, plus `Layer.effect`;
  - `Schema.TaggedError`;
  - `Effect.catch*`;
  - `Result`, not `Either`.

  For v4 APIs, read `~/Documents/Dev/Projects/HCCNA/repos/effect/LLMS.md`. It is
  read-only: never import from it.
- The only bodies ever published under `scentiment-mqtt-prod/` are
  `{"action":"PING","payload":{"userid":"<SCENT_ROUTE_ID>"}}` and
  `{"action":"GET_STATUS","payload":{}}`. They are QoS 1, never retained, and go only to
  `scentiment-mqtt-prod/device/<valid id>`.
- Retained messages go only under `scent-control/v1/`, and only through `retainedPublish`
  (Task 3).
- Timing:
  - ping every 30 s;
  - wait 15 s for an answer;
  - online for 75 s after hearing from a diffuser;
  - `GET_STATUS` at most every 300 s;
  - readers ignore any time more than 86 400 s ahead of their clock.
- Topics:
  - `scent-control/v1/state/<deviceId>`;
  - `scent-control/v1/listener`;
  - probes under `scent-control/v1/probe/server/<8 hex>`.
- Settings come only from the environment: `SCENT_BROKER_URL`, `SCENT_BROKER_USERNAME`,
  `SCENT_BROKER_PASSWORD` and `SCENT_ROUTE_ID`.
  - Locally they come from the repo-root `.env` plus `tools/.env.local`. On Railway they
    are service variables.
  - The password is never printed, logged, put on a command line or typed by anyone. On
    Railway it is a reference to the broker's own variable.
  - The other three aren't secrets, but they stay out of tracked files and out of printed
    output.
- Logs never contain passwords, settings values or message bodies. Device IDs in logs are
  written as `…` plus their last 4 characters.
- Test data:
  - devices `TESTDEVICE01` (Air 2) and `TESTDEVICE02` (HVAC 2);
  - route ID `example-route`;
  - times near `1_792_510_200`.

  No real device ID, route ID, broker host, email or personal name goes in any tracked
  file, commit message or PR body. Verification commands that read the live broker print
  **counts**, never topics or bodies.
- Never contact Scentiment's servers.
- `test-broker` is redeployed or restarted only in Task 7, after the owner confirms then
  and there. No other task changes it.
- After every task, `bunx turbo run build test lint fmt:check` passes from the repo root.
- Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Publishing while disconnected.** MQTT.js queues QoS 1 publishes made while offline
   and flushes them on reconnect, which would burst stale `PING`s and `GET_STATUS`es at
   the diffusers. Nothing may be published unless connected. The test is in Task 4.
2. **The listener's own records echoing back.** It subscribes to `scent-control/v1/#`, so
   it hears every record it publishes. Hearing one must not publish again. The test is in
   Task 3.
3. **Two listeners during a deploy, with different memories.** They must converge after
   one exchange, with no ping-pong. The test is in Task 3.
4. **A message with no status fields** (`led:50`, an `ALREADY_ADDED` acknowledgement). It
   moves `heardAt` and never removes or ages a field. The test is in Task 3.
5. **The Mac's pending sends.** A listener reading made after a send clears it as
   confirmed. One made before the send, such as the listener republishing an old report
   every 30 s, must not. The test is in Task 6.

**Interfaces:**

  constants.
- Produces, from `record.ts`:
  - `FIELD_KEYS`: `["power","intensity","charging","battery","fan","gas_pump","light","rssi"] as const`;
  - `type FieldKey`;
  - `interface FieldReading { value: number; at: number }`;
  - `interface ConnectedInfo extends Connected { at: number }`;
  - `interface DeviceRecord { heardAt?: number; pingAt?: number; askedAt?: number; fields: Partial<Record<FieldKey, FieldReading>>; connected?: ConnectedInfo }`;
  - `type Memory = ReadonlyMap<string, DeviceRecord>`;
  - `EMPTY_RECORD`;
  - `mergeRecords(a, b): DeviceRecord`;
  - `samePublished(a, b): boolean` (equal, ignoring `askedAt`);
  - `isCurrent(record, key): boolean`;
  - `hearMessage(record: DeviceRecord | undefined, message: MqttMessage, at: number): DeviceRecord`;
  - `needsStatus(record, now): boolean`.
- Produces, from `payloads.ts`:
  - `renderState(record, updatedAt): string`;
  - `parseState(body: Uint8Array, now: number): DeviceRecord | undefined`;
  - `renderHeartbeat(at, startedAt): string`;
  - `WILL_BODY`.
- Produces, from `gates.ts`:
  - `interface Publish { topic: string; body: string; qos: 1; retain: boolean }`;
  - `retainedPublish(topic, body): Publish | undefined`;
  - `commandPublish(deviceId, command: ListenerCommand): Publish | undefined`.
- Produces, from `steps.ts`:
  - `interface Step { memory: Memory; publishes: ReadonlyArray<Publish> }`;
  - `onConnAck(memory, now, startedAt): ReadonlyArray<Publish>`;
  - `onMessage(memory, topic, body: Uint8Array, now): Step`;
  - `onTick(memory, now, routeId, startedAt): Step`.

**The rules the functions implement:**
- **`mergeRecords`:**
  - each field keeps the reading with the later `at`;
  - `heardAt`, `pingAt` and `askedAt` keep the maximum;
  - `connected` keeps the one with the later `at`.
- **`isCurrent`:** the reading exists, and there is no `connected`, or the reading's `at`
  is at least `connected.at`.
- **`hearMessage`:**
  - sets `heardAt = at`;
  - stores every status field the message carries as `{ value, at }` (`gasPump` becomes
    `gas_pump`), plus `rssi`;
  - stores `connected` with `at`;
  - leaves every other field untouched.
- **`needsStatus`:**

  ```
  reachable  = heardAt defined and now - heardAt <= ONLINE_FOR_S
  recently   = askedAt defined and now - askedAt < STALE_AFTER_S
  unknown    = not isCurrent(power) or not isCurrent(intensity)
  newest     = the later of power.at and intensity.at, over those present
  stale      = newest undefined or now - newest > STALE_AFTER_S
  needsStatus = reachable and not recently and (unknown or stale)
  ```
- **`renderState`:** spec §6.4 exactly:
  - `v` 1, `updated_at`, then `heard_at` and `ping_at` only when defined;
  - `fields` with only the readings present, keyed by `FieldKey`;
  - `connected` only when defined;
  - never `askedAt`.
- **`parseState`** returns `undefined` for:
  - an empty body or invalid JSON;
  - any `v` other than 1;
  - a wrong shape;
  - any time more than `DAY_AHEAD_S` ahead of `now`.

  Field keys it doesn't know are dropped.
- **`retainedPublish`** gives `{ topic, body, qos: 1, retain: true }` only when:
  - the topic starts with `APP_PREFIX`;
  - something follows the prefix;
  - it contains no `+` or `#`.

  Otherwise it gives `undefined`.
- **`commandPublish`** gives
  `{ topic: deviceTopic(id), body: commandBody(command), qos: 1, retain: false }` only for
  a valid ID and, for `PING`, a non-empty `routeId`.
- **`onConnAck`:** the heartbeat first, then every record's state, in device ID order.
- **`onMessage`:**
  - **Under `APP_PREFIX`:**
    - `state/<id>`: parse it. If it's usable, merge it into memory, and publish the merged
      record only if `samePublished(merged, parsed)` is false.
    - `schedule/<id>` with a non-empty body: the ID becomes known (with `EMPTY_RECORD`)
      and nothing is published.
    - Anything else: nothing.
  - **Otherwise:** run `parseMqtt`.
    - `toDevice`, or a missing or invalid ID: nothing.
    - Anything else: `hearMessage`, then publish that device's state.
- **`onTick`:** publishes, in order:
  1. the heartbeat;
  2. for each known ID, in order:
     - `PING`, setting `pingAt = now`;
     - `GET_STATUS` if `needsStatus` held before this tick's changes, setting
       `askedAt = now`;
     - its state.

- Produces, from `log.ts`: `shortId(id: string): string`, giving `"…" + id.slice(-4)`.
- Produces, from `run.ts`: `runListener: Effect.Effect<never, never, Broker | ListenerConfig>`.

**Behavior:**
- **`Broker.make`** is scoped. It calls MQTT.js `connect(brokerUrl, …)` with:
  - `protocolVersion: 4`, `clean: true`;
  - client ID `scent-control-listener-` plus `randomHex8()`;
  - the username and the unwrapped password;
  - `reconnectPeriod: 5000`;
  - `will: { topic: LISTENER_TOPIC, payload: WILL_BODY, qos: 1, retain: true }`.

  On top of that:
  - incoming packets up to 256 KiB must be accepted (spec §6.1). Check that MQTT.js sets
    no lower limit for MQTT 3.1.1, and write what you found in the ledger;
  - `publish` fails with `BrokerError` while the client isn't connected, so nothing is
    ever queued offline (Review Focus 1);
  - the finalizer ends the client with a clean DISCONNECT, so no will is sent.
- **`runListener`:**
  - It keeps a `Ref<Memory>` and `startedAt`.
  - For each event:
    - `ConnAck` → subscribe to `[SUBSCRIBE_ALL, SUBSCRIBE_APP]`, then publish
      `onConnAck(...)`;
    - `Message` → apply `onMessage`;
    - `Closed` → log it.
  - Every `PING_EVERY_S` it applies `onTick`, but only while `isConnected`.
  - A failed publish logs `BrokerError` (its reason only) and the listener carries on.
  - The clock is Effect's `Clock`, in whole seconds.
  - Logs follow the global constraints, with device IDs through `shortId`.
- **`main.ts`:** `BunRuntime.runMain` of `runListener`, provided with
  `Layer.effect(ListenerConfig, …)` and `Layer.effect(Broker, …)`. SIGTERM interrupts it,
  which runs the finalizer.

**Behavior:**
- **A usable state record** for a valid ID:
  - the device is created if it's unknown;
  - for each field key `Field::from_key` knows, the reading is adopted as

  every 30 s and would fill the capped log.
- **The heartbeat:**
  - a heartbeat sets `listener`;
  - a running one also sets `listener_seen_at` to its `at`;
  - the will (`running: false`) leaves `listener_seen_at` alone.

  - running → `"Listener: running"`;
  - else, if `seen_at` is known → `"Listener: not running, last seen {ago}"`, using
    `ui::format::ago`;
  - else, if a heartbeat was seen → `"Listener: not running"`;
  - else → `"Listener: not seen yet"`.

  It is shown under the broker status line, with a `status_dot`: green when running,
  grey otherwise.
- **The hero's note:** when the newest power or intensity reading is from before
  `connected_at` and nothing is pending, the note reads
  `"Not known since it reconnected {ago}"`, with `ago` of `connected_at`. The power and
  level shown are none.
